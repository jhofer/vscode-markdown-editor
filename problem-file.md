# Security Roles Catalog

## Scope

The catalog of Dynamics security roles used in ZVPM, the Business Units and Teams they are
attached to, and how a user is provisioned into them. For per-entity CRUD privilege detail of
each role, see the generated role documentation in `dynamics-solutions` — this page deliberately
does not reproduce that table (it is regenerated from the solution and would drift out of date
immediately).

This page is **not** about:

| Not covered here | Covered in |
|---|---|
| Which persona (ZVPM-AP01…AP33) uses which of these roles | [18-user-personas-access-model.md](18-user-personas-access-model.md) |
| Privileged/administrative roles (System Administrator, Azure RBAC, PAM) | [19-administrative-users-privileged-access.md](19-administrative-users-privileged-access.md) |
| Field/column-level security profiles | [20-column-field-level-security.md](20-column-field-level-security.md) |
| The plugin/Azure Function that performs provisioning | [14-user-provisioning.md](14-user-provisioning.md) |

## Per-entity privilege detail

Each security role's full entity-level Create/Read/Write/Delete/Append/AppendTo/Assign/Share
matrix is generated directly from the Dynamics solution — one Markdown file per role — and must
not be duplicated here:

- [Security roles index](https://dev.azure.com/zurichinsurance/ZVPM/_git/dynamics-solutions?path=/Docs/roles.md) (`dynamics-solutions/Docs/roles.md`)
- Individual role docs: `https://dev.azure.com/zurichinsurance/ZVPM/_git/dynamics-solutions?path=/Docs/roles/<Role-Name>.md`

These are regenerated by `tools/generate_roles_md.ps1` whenever the solution changes — do not
hand-edit them, and do not copy their tables into wiki pages. If a role name below has no
matching file in that index, the role's privileges are not yet covered by generated
documentation (see the naming caveats at the end of this page).

## Role categories

**Base roles, assigned directly to users**

- Base User — baseline Dynamics access, assigned to every active user
- BU Shared — lets a Generalagent/GA-Broker Operations user see records owned by their GA-Broker teams
- Business Support — full access to (almost) all record types; used so support staff never need to log on as `adm` on PROD. Settings and records originating from interfaces remain protected.

**Roles for special functions, assigned directly to users or teams**

- Excel Export
- Role Assignment

**Owner-team roles**

Assigned only to the team that owns the corresponding bundle of records, so that team can act as
record owner:

- Broker (Owner) — owns the Broker bundle
- CI Broker (Owner) — owns the CI Broker bundle
- Agency (Owner) — owns the Agentur bundle
- ZVPM Management (Owner) — owns the Z-Employees and the Zürich Versicherungsgesellschaft company record

### Naming caveats (reproduced as found in the source documentation)

- "Broker CIBOMI" and "CI Broker CIBOMI" are documented as distinct roles despite the very
  similar name — reproduced as-is rather than assumed to be a duplicate.
- Some AP-persona pages map a *team* to a role whose name doesn't quite match the team's own
  name (e.g. team "CI Broker CIBOMA" mapped to role "CI Broker CIBOMI") — likely drift from
  copy-pasted template pages, not corrected here.
- "Report User ZEEU" and its owning team "Z-Employee Edit User" (used by the Z01/Z03 Role
  Assignment persona) have no matching file in the generated roles index at the time of this
  migration — flagged rather than linked to a guessed file.

## Provisioning

Standard (non-administrative) users are provisioned through the IT-Shop:

1. Every active user is granted **Base Role**.
2. The user is added to the Entra ID license group `Dyn365-CH-License-SalesEnterprise`.
3. The user is added to the environment's Entra ID security group
   (`Dyn365-CH-ZVPM-UAT` for Live, `Dyn365-CH-ZVPM-PROD` for Prod).
4. The user is created in Dynamics, assigned to a Business Unit and to one or more Teams, and
   granted security role(s) (at minimum "ZVP Basis") — all driven by the user's IT-Shop profile.

Competence levels used during ordering: level 0 requires no approval, level 50 requires approval
by a designated approver.

The concrete mechanism that turns an IT-Shop profile into a Dynamics user/BU/team/role assignment
— the `zch_UserProvisioningConfig`/`zch_UserProvisioning` tables, the plugin, and the Azure
Function — is documented in [14-user-provisioning.md](14-user-provisioning.md); this page only
describes the upstream IT-Shop process that produces the profile.

Administrative/privileged users are **not** provisioned through the IT-Shop — see
[19-administrative-users-privileged-access.md](19-administrative-users-privileged-access.md).
